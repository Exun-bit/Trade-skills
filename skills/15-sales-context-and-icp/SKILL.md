# Sales Context and ICP

## Objective
Create the shared context that other sales skills can read instead of repeatedly rebuilding assumptions.

## Workflow
1. Read config/company-profile.md for current company facts.
2. Read config/sales-context.md for the user's stable sales motion.
3. Define the target account: brand type, product category, geography, approximate scale when observable, and customization relevance.
4. Define the target buyer: founder / owner, sourcing / procurement, production, product development, or wholesale / operations.
5. Define buyer problems as hypotheses unless directly evidenced.
6. Define approved proof points from the current company profile.
7. Create qualification criteria and disqualifiers.
8. Update the context only when new evidence materially changes the sales strategy.

## Output
- ICP
- Buyer personas
- Likely buying criteria
- Qualification rules
- Disqualifiers
- Approved value propositions
- Proof points
- Unknowns

## Rules
- Do not hard-code one company into the skill.
- Do not treat an ideal customer as a confirmed buyer.
- Do not invent pain points or decision-maker authority.
